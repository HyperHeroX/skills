# CoWork 企業高階教學與商業簡報製作規範 (CoWork Presentation Skill)

本規範深度整合自 Hiro 長期累積之「企業高階教學簡報產生規範」、「教學/CLAUDE.md 簡報規範」與 CoWork 憲法原則，專門適用於所有企業高階內訓、商業演講、技術分享與提案簡報製作。所有 AI 在產出簡報（HTML PPT / PPTX）時，**必須強制遵循本規範**，嚴格禁止小字堆疊與擁擠排版，嚴格禁止整份簡報套用單一卡片模板，嚴格落實 SVG 幾何防溢出與台灣標準用語。

---

## 一、核心排版三大定律（Bold, Big & Full-Bleed）

### 定律 1：文字要大（Bold & Big，可遠距閱覽）

教室最後一排、會議室長桌末端必須能清楚閱讀每一行字。嚴格禁止為了塞入資訊而縮小文字。

- **封面主標題 (`.hero` / `h1.title`)**：`clamp(56px, 6.5vw, 84px)`，粗體 800，高對比漸層或明亮白。
- **頁面次標題 (`.h2`)**：`clamp(34px, 3.8vw, 48px)`，粗體 700。
- **卡片/模組標題 (`h3` / `h4`)**：`clamp(24px, 2.5vw, 32px)`，粗體 700，必須搭配 Emoji 或圖示。
- **卡片內文 / 正文 (`p`, `li`, `td`)**：`clamp(18px, 1.8vw, 24px)`，行高 1.55 ~ 1.65。
- **大數字強調標記 (`.bignum`)**：`clamp(68px, 8vw, 110px)`，超粗體，搭配單行商業解讀。
- **字級絕對下限**：所有可見文字（含提示、表格、圖說、SVG 標籤、footer 與控制項）依實際渲染尺寸計算，**絕對不得小於 16 CSS px**（正文一律維持 18px 以上）。RWD 可流體縮放，但 `clamp()` 下限及 SVG 縮放後的文字均嚴禁跌破 16px。

### 定律 2：每頁必須有明顯提示（Visual Callout & Prompts）

每一頁簡報必須穿插至少一個與該頁核心訊息直接呼應的**高對比提示元件**，引導聽眾與高階主管抓住痛點：

- **樣式要求**：左側或頂部具備 4px 亮彩強調邊框（亮藍 `#3b82f6`、警示橙 `#f97316`、高危紅 `#ef4444`、合規綠 `#10b981`），背景使用 8%~15% 半透明光暈，文字採純白 `#f8fafc`。
- **提示類別範例**：
  - `💡 關鍵決策提示`：直擊商業影響或策略方向。
  - `🚨 高階防衛警示`：揭示合規風險或破口代價。
  - `⚖️ 董事受託責任`：點明法律責任與監管要求。
  - `📋 實戰檢核指引`：提供立即可用的行動指針。

### 定律 3：動態架構圖與流程圖必須「獨立一頁且滿版」（Full-Bleed Visual Slide）

凡包含動態流程圖、系統架構圖（如嵐叔動態架構圖 GIF）、Sankey、資料流全景圖等複雜視覺時：

- **嚴禁左右分割硬塞卡片**：禁止將圖表縮小置於半邊、旁邊塞文字卡片，此舉會造成圖表文字看不清、卡片字體嚴重縮小。
- **必須獨立一頁滿版展示**：
  - 頂部保留精煉標題與類別徽章。
  - 中間畫布最大化滿版且可放大：寬高使用可用空間，四周安全留白最多 50px；提供放大控制、滑鼠滾輪縮放與 Escape 關閉，圖中文字不得因 RWD 縮至 16 CSS px 以下。
  - 底部配置單行醒目戰略解讀提示列。
- **詳細架構解析另外獨立成頁**：將架構圖之「關鍵破口分析」、「防禦控制點」獨立為後續 1~2 頁之專門解析頁，以大卡片、大字級深入推演。

## 二、版面變化與 10 大圖說選型體系（拒絕單一模板套版）

**每一頁先做內容判斷，再決定版型！**
整份簡報嚴禁反覆套用相同左右分割或卡片結構。版型變化必須有教學與簡報敘事理由，依內容實際關係從「10 大圖說選型矩陣」精準選擇：

| 內容的實際關係 | 優先選用圖說版型 | 核心必須交代之要素 |
| --- | --- | --- |
| 1. 操作步驟、前置與完成條件 | **流程圖 (Flowchart)** | 起點、處理、判斷條件、成功出口與必要的失敗/例外出口 |
| 2. 不同角色交換請求、事件與時序 | **時序圖 (Sequence Diagram)** | 角色生命線、傳送方向、時序先後與回傳路徑 |
| 3. 責任跨越不同人員、系統或部門 | **泳道圖 / 責任矩陣 (Swimlane Diagram)** | 誰負責、何時交接、交接憑據與驗收產物 |
| 4. 元件組成、防護邊界或分層架構 | **分層架構圖 (Layered Architecture)** | 內外邊界、每層責任、允許的依賴方向與微隔離區域 |
| 5. 條件不同而選擇不同處置路徑 | **決策分支圖 (Decision Tree)** | 判斷條件分支、各分支商業後果、停止條件 |
| 6. 物件遭遇事件後改變狀態 | **狀態轉移圖 (State Diagram)** | 初始狀態、觸發事件、可用轉移、拒絕維持原狀 |
| 7. 組織單元、威脅情報與系統依賴 | **關係相依圖 (Dependency Graph)** | 節點定義、連線關係、影響擴散半徑 |
| 8. 不同方案依同一維度橫向比較 | **對照卡 / 比較矩陣 (Comparison Matrix)** | 一致的比較面向、各方案優勢、限制與適用邊界 |
| 9. 真實數量、損失尺度與經濟算式 | **Bento Grid 模組 + 大數字 (`.bignum`)** | 大數字視覺衝擊、單位、精準算式與單行商業戰略解讀 |
| 10. 高階合約、決策邊界與演練指令 | **商用決策契約塊 (Executive Decision Block)** | 明確任務角色 (Role/Task)、邊界限制 (Context)、輸出要求與驗收判準 |

## 三、高階商務與教學簡報之 8 大核心特色（必須完整體現）

1. **主軸頁／全景知識地圖 (Curriculum Knowledge Tree)**：
   - 每份簡報在開場後，必須有一頁「全景知識結構地圖」，標記當前章節在整體課程或體系中的戰略定位與前後銜接。
2. **現場即時互動／破題二選一 (Interactive Scenario Quiz)**：
   - 包含現場提問、情境二選一抉擇卡（如：被勒索當下是否付贖金？）、聽眾表決或反例除錯卡，引導聽眾主動參與思考。
3. **大數字標記與商業解讀 (`.bignum` + Insight)**：
   - 善用超大數字（如 `36.79%` 投資極限、`4hr` 黃金中斷上限、`1.5億` 頂格罰鍰）創造視覺錨點，下配一行直擊心靈的高階商業解讀。
4. **時序圖與責任泳道圖視覺化**：
   - 在事故剖析與沙盤推演中，使用清楚的時序圖（Sequence）與跨角色責任泳道圖（CEO/CFO/COO/CISO），嚴禁只用單純條列文字。
5. **高階商用可複製決策指引契約塊 (Executive Contract Blocks)**：
   - 在治理或實戰章節最後，提供具備任務角色、邊界限制、具體指令與驗收標準的標準指引塊。
6. **流程圖說語意動畫與逐步推演 (Semantic Animation & Controls)**：
   - 呈現流程時逐步演繹「觸發、處理、判斷、結果」；具備上一步、下一步、播放/暫停控制列，並在 `prefers-reduced-motion` 下維持靜態完整可讀。
7. **嚴禁在學員/聽眾畫面提醒講師**：
   - 不在學員投影畫面顯示講師操作提醒或遮擋操作列；講稿走 Presenter View (`S` 鍵) 演講者雙螢幕視圖或獨立同名 Markdown。
8. **單檔離線自洽與零 CDN 依賴**：
   - CSS、JavaScript、SVG 與圖片完全內嵌或本機自洽；簡報檔案搬移至任何離線電腦，均能完美展示與互動。

## 四、版面空間與滿版規範（50px 安全留白）

1. **四周留白上限**：主要內容與視窗邊界空白不得超過 50px；導覽列採浮動控制，不以過大的底部 padding 留空。
2. **上下左右滿版流動**：`.slide` 與主要內容填滿可用 viewport；容器及卡片網格使用 `width: 100%`，避免固定窄版 `max-width` 或造成空白的固定 `min-width`。
3. **SVG 圖表填滿圖表區**：SVG 根節點填滿圖表區或卡片的可用寬度，左右不留不必要空白；保留比例、完整資料，透過調整 `viewBox`、容器或重新排版填滿，不可裁切或拉伸變形。
4. **不可靜默裁切**：`.slide` 維持 `position: absolute; inset: 0;`；內容超出視口時提供可操作捲動，不得讓文字或圖表被裁掉。
5. **逐頁選擇版型並消除無效留白**：依該頁內容關係安排圖表、圖片、流程或卡片順序；不得讓卡片下半部或頁面底部留下大片空白。
6. **滑鼠滾輪翻頁**：每個滾輪手勢最多翻一頁；可捲動內容先捲到邊界，放大圖表中的滾輪用於縮放。

## 五、高對比度文字規範

投影機與大型顯示器常見對比不足問題，嚴格執行以下規範：

1. **傳遞資訊文字透明度 ≥ 0.85**：
   - 主要文字一律使用 `#f8fafc` 或 `#ffffff`。
   - 次要說明文字一律使用 `#cbd5e1` 或 `#e2e8f0`。
   - 輔助文字（頁尾、來源）使用 `#94a3b8`。
   - **禁止**使用 `rgba(255,255,255,0.4)` 等低於 0.7 的發灰文字。
2. **禁止純靠透明度表達層級**：層級區分一律透過字級大小、粗細（Font Weight 700/800）與強調色（Accent Color）展現。

## 六、演講者模式與逐字稿標準

1. **上台演講節奏**：每分鐘約 240 字標準語速（每頁分配約 1~2 分鐘）。
2. **雙螢幕演講者模式 (`S` 鍵)**：
   - 支援即時雙螢幕同步、當前頁/下一頁縮圖預覽、累計計時器、以及大字體逐字稿（Speaker Notes）。
   - 每頁投影片下方或內部 `<aside class="notes">` 必須包含 150–300 字口語化講稿，供講師上台直接念稿。

## 七、交付與驗收標準

1. **離線單檔與可攜性**：
   - 樣式、腳本與本機素材路徑必須自洽，可直接以 `file://` 開啟，嚴禁外部不明 CDN 依賴。
2. **自動化實機渲染驗核**：
   - 產出後透過 Chrome Headless 或等效瀏覽器實測封面、內容頁、滿版架構圖、時序/泳道圖與案例頁；在桌機、平板、手機檢查 16px/18px 字級底線、SVG 滿版、圖表放大、滾輪翻頁、無水平溢出與無靜默裁切，並記錄實際 viewport 與瀏覽器版本。

## 八、SVG 圖說工程規範（強制）

1. **填色防護**：開放路徑（曲線、折線、L 形）一律 `fill="none"`；建議全域防護 `svg path:not([fill]) { fill: none; }`——瀏覽器對未設 fill 的開放路徑會**預設黑填滿**，形成黑色色塊遮蔽內容。
2. **定義本地化與 id 唯一**：`marker`／`linearGradient`／`clipPath` 必須定義在**引用它的同一個 SVG 內**，且 id 全檔唯一（建議頁碼前綴，如 `ar14`）。跨 SVG 引用 `url(#id)` 在來源頁 `display:none` 時失效——箭頭與漸層直接消失。
3. **嚴禁 HTML 混入 SVG**：SVG `<text>` 內**嚴禁** `<strong>`／`<b>`／`<em>`／`<br>` 等 HTML 標籤——HTML 解析器在 SVG 外來內容中遇到未知標籤會**脫離 SVG**，後續節點被踢出成漂浮文字、圖形整批消失。強調一律使用 `font-weight`／`fill`／`<tspan>`。
4. **字級下限**：圖內文字渲染後不得低於 **16px**（正文維持 18px 以上，依 viewBox 縮放比例換算實際渲染尺寸；以 `getComputedStyle` 量測為準）。
5. **不重疊、不溢出**：文字與框線、文字與文字不得重疊（多行間距 ≥26px）；標籤長度預留 bbox 緩衝，不得溢出所屬框或 viewBox 邊界。
6. **資料流動畫**：連接線一律具流動動畫（`stroke-dasharray`＋`dashoffset` keyframes，或 `animateMotion` 光點），`prefers-reduced-motion` 下自動轉為靜態完整可讀。
7. **可放大**：每個滿版圖說容器提供放大檢視（滾輪縮放 1–5×、Esc 關閉）。
8. **交付前自動偵測**：以 headless 瀏覽器掃描並歸零五類缺陷——① 無 fill 屬性路徑（黑塊）② 跨 SVG id 引用（線段消失）③ SVG text 溢出 bbox ④ 文字 bbox 重疊 ⑤ 任意文字 <16px。

## 九、SVG 多卡幾何佈局與防框體溢出鐵律（實戰淬鍊）

在 SVG 繪製多欄卡片、流程步驟與泳道圖時，必須遵循嚴格的幾何尺寸與文字長度換算：

1. **多欄卡片寬度與高度底線**：
   - 在標準 1120~1140 寬度 viewBox 下：
     - **4 欄等寬卡片**：卡片寬度不得小於 **255px**（建議寬度 255~260px，高度 380~390px，頂部徽章寬度 $\ge 225\text{px}$）。
     - **3 欄等寬卡片**：卡片寬度不得小於 **345px**（建議寬度 345~350px，高度 380~390px，頂部徽章寬度 $\ge 305\text{px}$）。
   - **嚴禁在 4 欄佈局使用 $\le 200\text{px}$ 的窄卡片**：窄卡片邊界嚴重不足，條列文字將直接暴衝穿出邊框 50~80px 造成嚴重錯版。
2. **中文字長度與卡片寬度換算極限**：
   - 每個中文字在 16~18px 字級下約佔用 16~18px 寬度，卡片左右兩側必須各預留至少 15px 安全邊距。
   - 寬度 200px 的卡片扣除邊距後，單行最多僅能容納 9~10 個中文字；若有 15~18 字之長句，必須進行文字折行或改用滿版佈局。
3. **複雜多步邏輯改採「滿版橫向階梯排版 (Staircase Rows)」**：
   - 遇 5 Whys RCA、石川魚骨圖、多維度深層事件鏈等文字資訊較多的場景，**嚴禁硬塞 5 個極窄直向卡片**（$\le 180\text{px}$ 會嚴重溢出數百 px）。
   - 一律改採**滿版橫向階梯式卡片（Staircase Rows，寬度 $\ge 1000\text{px}$，高度 68~78px）**，或將標籤框寬度拓寬至 130~170px，確保文字不穿框、不破版。
4. **置中錨點座標數學一致性**：
   - 當文字標籤設置 `text-anchor="middle"` 時，其 `x` 座標必須精準等於 `rect_x + rect_width / 2`，嚴禁座標偏置導致文字與邊框碰撞。
5. **泳道圖 (Swimlane) 嚴格切分 X 軸**：
   - 泳道底框、角色標章、狀態標籤、說明內文必須在 X 軸上完全區隔（如：底框寬 960、角色標章 35~180、狀態標籤 195~295、內文 315 起始），嚴禁標籤與內文重疊。

## 十、台灣標準資安與軟體工程用語規範（強制禁絕中國用語）

簡報製作一律採用繁體中文（台灣標準），**嚴禁使用中國大陸技術用語**。在產出與交付前，必須強制對照並轉換為台灣業界與法規標準用語：

| 中國大陸用語 | 台灣標準資安與技術用語 | 適用情境與保留例外 |
| :--- | :--- | :--- |
| **渠道** | **管道** | 通報管道、溝通管道、關懷管道、傳播管道 |
| **審計** | **稽核** | 第三方獨立稽核、安全稽核、稽核日誌、稽核報告。<br>⚠️ **法定例外**：精準保留證交法法定專有名詞「**審計委員會**」 |
| **黑客** | **駭客** | 白帽駭客、駭客組織、駭客勒索、駭客入侵 |
| **網絡** | **網路** | 網路架構、工控網路、平坦網路、斷網隔離 |
| **內存** | **記憶體** | 記憶體鑑識、記憶體映像、記憶體中執行 |
| **登錄** | **登入** | 登入後台、單一登入 (SSO)、異常登入通報 |
| **把控** | **掌控／掌握** | 掌握進度、掌控風險、節奏掌握 |
| **鏈接** | **連結** | 時序連結、通訊連結、網址連結 |

## 十一、自動化交付前檢驗流程（Pre-Delivery Verification）

在完成簡報建置與組裝後，必須執行自動化驗證腳本，嚴格稽核以下項目，全數通過方可交付：

1. **幾何防溢出稽核**：
   - 遍歷所有 SVG，計算每個 `<text>` 之長度與座標，比對其所屬 `<rect>` 邊界，確認無任何文字超出卡片或圖形外緣。
2. **用語合規稽核**：
   - 掃描全份簡報（HTML / 腳本 / 片段），搜尋中國大陸技術詞彙（渠道、非委員會審計、黑客、網絡、內存、登錄、代碼、構建等），確保出現次數為 **0**。
3. **投影片與講稿對齊稽核**：
   - 檢查投影片數量與 `<aside class="notes">` 演講者講稿數量必須為 **1:1 精準對齊**（如 26 頁簡報對應 26 則講稿），且每則講稿字數在 150~300 字區間。
4. **文字字級底線稽核**：
   - 檢查所有文字元件與 SVG `<text>`，確保無低於 16px 的微小文字。
5. **英文縮寫中文釋義稽核**：掃描所有學員可見或可取得的投影片、圖表/SVG、提示、互動介面與講義；確認每次出現的英文專業縮寫均緊鄰繁體中文意涵（如 `BJR（商業判斷原則）`），不得僅在前文或詞彙表一次性解釋。

## 十二、英文縮寫逐次標註中文釋義規範 (Acronym Clarification)

高階經理人與非技術背景學員常對英文縮寫感到生疏或困惑。**凡學員可見或可取得的簡報、教材、講義及課堂互動內容中，任何英文專業縮寫、首字母詞或字母代號每次出現，都必須立即在旁標註繁體中文意涵**（例如：`BJR（商業判斷原則）`、`CISO（資安長）`），嚴禁孤立的英文縮寫堆疊。

### 1. 執行標準
- **標題、次標、卡片標題**：英文縮寫每次出現都以 `縮寫（中文意涵）` 緊鄰標註，例如 `BJR（商業判斷原則）`。

## 十三、高階專業教學講稿製作規範 (Executive Lecture Script Specification)

本章節規範所有企業高階內訓、商業演講與技術課程之口語講稿撰寫標準。講稿是簡報的靈魂與知識的載體，任何講稿產出**必須強制遵循以下八大核心規範**：

### 1. 模組化逐時獨立單元化（拒絕單體巨型文件）
- **獨立建檔原則**：講稿必須以「一小時（50分鐘教學單元）一檔」為單位獨立建檔（命名規範：`DayXX_HXX_主題_講稿.md` 或 `02_講稿_第N節_{主題}.md`）。
- **自洽與高內聚性**：每一小時單元必須具備完整的開場、理論、案例、決策與結尾，具備獨立可讀性與演講自洽性；同時單元間應具備清晰的前後呼應與章節定位，嚴禁將全天或多小時內容揉合為龐大雜亂的單體文件。

### 2. 精準口語語速與字數基準（120 字／分鐘，逐字稿等級）
- **逐字稿（Verbatim Script）交付**：講稿必須達到「講師登台可直接照唸」的口語流暢度，杜絕空泛的大綱條列、投影片備忘短文或簡短摘要。
- **標準語速校準**：講述節奏嚴格以 **每分鐘 120 字**（繁體中文口語逐字稿）為基準。
- **單元標準字數**：針對 50 分鐘標準教學小時（規劃為 40–45 分鐘逐字精準講授 + 5–10 分鐘學員互動與答辯），口語有效字數需達 **4,800 至 5,800 字**。

### 3. 五大標準時間段結構（時間軸精準切割）
每一份逐時講稿必須嚴格包含以下五大標準階段標記：
1. `00:00–05:00｜導言破題、課程目標與今日定位`：以真實痛點、商業危機或引人入勝的歷史案例破題，明確交代該小時之學習目標（Learning Outcomes）與全域地圖定位。
2. `05:00–20:00｜核心理論：架構標準、制度規範與底層原理`：深入解析國際權威標準規範（如 NIST、ISO/IEC、RFC、OWASP、法規命令等），透徹剖析底層架構設計、核心機制與數學/密碼學原理。
3. `20:00–35:00｜企業真實情境：衝突決策、架構對抗與實務推演`：注入具備飽滿技術肉量與商業博弈之真實企業攻防情境（包含跨角色角力、深層機制、極限狀態下的取捨），展現高階實務處置深度。
4. `35:00–45:00｜高階決策矩陣、常見誤區迷思辨析與考點直擊`：以對比矩陣或決策表格深入辨析三大常見技術/管理盲區，直擊認證考點、解題破題邏輯與高階決策心法（如 Think Like a Manager）。
5. `45:00–50:00｜課堂關鍵互動總結、課後練習與下小時銜接`：包含現場思考淬煉提問、落地實踐檢核清單（Actionable Checklist）與承先啟後的下小時預告。

### 4. 事實查核與權威標準映射（Fact-Checking & Authority Mapping）
- 講稿中提及的所有技術協定（如 SAML/OAuth/OIDC）、法規時限（如 GDPR 72小時、SEC 4天、資通法 1-2-4小時）、標準編號（如 NIST SP 800-63B/61r2/218、ISO/IEC 27001/27035、RFC 3227、OWASP Top 10:2021、SLSA 框架）、商業法律原則（如 BJR 商業判斷法則、Due Care/Due Diligence 受託責任）必須具備確鑿事實來源，嚴禁憑空捏造或參數錯置。

### 5. 杜絕空泛八股模板與重複無效廢話（Anti-Boilerplate Enforcement）
- 嚴格禁止任何八股重複的套版語句（如舊腳本反覆複製的八股填充詞句），每一單元之情境、推演與對話必須完全獨立、原創且切合當前主題。

### 6. 台灣標準資安與軟體工程用語鐵律（全面禁絕中國用語）
- 講稿全面使用繁體中文（台灣標準），產出前強制執行自動化掃描，違規次數歸零：
  `程式碼`（非代碼）、`駭客`（非黑客）、`稽核`（非審計，精準保留法定名詞「審計委員會」）、`記憶體`（非內存）、`登入`（非登錄）、`事後檢討／事後回顧`（非復盤）、`建置`（非構建）、`掌控／掌握`（非把控）、`使用者／客戶端`（非用戶）、`網路`（非網絡）、`連結`（非鏈接）、`管道`（非渠道）。

### 7. 學員可理解性之英文專業縮寫繁體中文釋義鐵律
- 所有專業英文縮寫、首字母詞（如 BJR、CISO、MFA、SBOM、WORM、RCA、OT、D&O 等），每次關鍵出現或首見時，必須緊鄰括號標註繁體中文釋義，確保非技術或跨領域學員能第一時間透徹吸收。

### 8. 跨模型第三方獨立盲審驗證（Independent Third-Party LLM Audit）
- 產出後必須調用環境內建 `pi` 工具（無交談式指令，輸入重定向 `< NUL`）調用獨立 LLM（如 `glm 5.3` / `gpt 5.6` 系列），從「學員吸收度、考證實務價值、管理階層思維、整體交付品質」進行盲審與抽查，評定合格（如 A 級）後方可交付。

## 附錄：教學簡報標準管線（講稿驅動，實戰修訂）


本附錄為完整生產規格，**通用於任何領域**之逐時／逐節教學簡報（30–40 頁/份）製作與重製；各條目源自實戰修訂，領域範例僅為註記。與前述通用規範衝突時，以本附錄為準。

### A. 內容來源與結構

1. 課程講稿／逐字稿（含逐字擴展段）**全文讀畢才動筆**；文字以「涵蓋講稿內容」為準，不以密度為指標。
2. 頁面結構映射講稿時間軸：導入 → 觀念 N 段 → 案例 → 教具任務 → 測驗；插圖頁／整合頁穿插於對應觀念之後。
3. 觀念標題用**講稿原題**（自創標題曾遭退件）；貫穿案例複用（各觀念回扣同一情境）。
4. 破題二選一、教具任務、測驗取自講稿原文；測驗含官方標準答案與講解要點。
5. 每份 30–40 頁；頁碼 01/NN–NN/NN 連續；全頁演講者備忘稿（150–300 字，240 字/分）。

### B. 卡片解剖學

1. 結構：h4 標題 → 大字正文（clamp(19px,1.55vw,23px)，行高 1.6）→ ❓ qstrip 優先問題 → foot 邊界/提示。
2. qstrip：紫左框、≥18px、**問句形式、每卡一問**；嚴禁與卡文重複（重複＝零加值，曾遭退件）。
3. 領先標籤（保護／手段／邊界／證據…）自動 `<b>` 加粗，重點可掃讀。
4. 卡 `overflow:hidden`、gap 收緊，防 foot 被擠出裁切。

### C. 版面整合（空曠頁）

1. 卡格移左（4 卡→2×2、2 卡→單欄、多卡→2×2），右側「🖼️ 已嵌入插圖」卡＋callout 縱向堆疊。
2. 插圖卡格式：`ifhead`（iftag「🖼️ 已嵌入插圖 0N」＋iftitle 中文圖說）＋`generated-illustration`。
3. 插圖規格：960×720、**無文字純圖形**、粉彩企業風（底 #f3f8ff、面板 #e6f4f2/#fff0ef/#fdf6ec/#f3f0ff、線 #5579b2/#355d67/#6c8da9、點綴 #28a878/#ea580c/#7c3aed/#f59e0b）。
4. 圖說由 iftitle 中文承載——無文字插圖自然免疫英文殘留與文字重疊。

### D. 配圖規範

1. 生成：codex exec 可用模型（帳權限制須存證，如 gpt-6.1-sol-med HTTP 400），平行批次每輪 4–6 張、單張 timeout 240–260s。
2. 嵌入：`data:image/svg+xml` URL 編碼＋`<img class="generated-illustration">`；**禁止裸 SVG 元素內聯**（無命名空間不渲染——已發生事故）。
3. 大圖嵌入前必跑**文字重疊稽核**：解析 text 座標→估寬→兩兩 bbox 碰撞＋畫布溢出，0 重疊才嵌入。
4. 提示詞不出現在頁面；留檔 `_build_*/配圖提示詞留檔*.md`（含生成腳本）。
5. 插圖斷言：無 `<text>`、無外部引用、viewBox 正確。

### E. 鐵律（四類體檢歸零制）

1. **全部可讀文字 ≥18px**，四類來源皆須體檢：attr 型 `font-size="N"`、CSS px 型（含「冒號空格」與個位數如 clamp(6px)、15px 漏網）、clamp 起點、LLM 圖內 `<style>` 宣告型。
2. SVG：開放路徑 `fill="none"`、marker id 本地唯一前綴、多圖內聯 id/class/style **命名空間隔離**、零外部引用（xmlns 除外）。
3. 台灣用語（稽核/駭客/資料/網路）；零 CDN 單檔離線；互動（滾輪/鍵盤/演講者/放大鏡）承襲母體框架。

### F. 第三方事實審核（領域中立）

1. 新增或填充內容彙出編號清單 → 獨立 LLM 審核，審核基準為**該領域之權威標準、規範與慣用法**＋台灣用語，嚴格僅輸出 JSON `{"issues":[{n,problem,fix}]}`。
2. 審核重點通用化：過度宣稱（如「可重放／百分之百」）、非通用控制（特定場所做法寫成通則）、控制項功能錯置、參數呈現為通用規範、法規相關判定（如個資）須註明依適用法規。
3. findings **逐條採納修正**；紀錄存證 `_build_*/審核紀錄/`（snippets＋verdict＋raw）。

### G. 工程管線與驗證對帳

1. 管線：`_build_*/frags`（head/tail/slidesXX/img）→ assemble（分節拼接＋INS 插頁＋token 替換＋頁碼重編）→ 體檢 → 對帳 → commit（版本號 +1）。
2. **計數互相對帳**：`<svg>` 總數＝各來源（手繪＋LLM＋vignette）加總；「div 數」與「grep 行數」差一行 CSS 屬正常；**只數 div 不數 svg 標籤為已發生之最大盲點，嚴禁重犯**。
3. 冪等修補：插入類修補用反向序（splice 後索引過時）＋已存在 guard；修完重跑只補缺口。
4. 腳本工程：含 `$` 變數/反引號之 bash 一律 payloads 寫檔執行（TS parser 攔截 `${}`）；`cd` 相對層數逐字數核對。
5. 已知教訓表（源自實戰，通用適用）：裸 SVG 元素不渲染／驗證只數 div／多行卡索引過時／grep 計行≠計次／LLM 圖 CSS 宣告型 font-size 盲點／填充內容重複卡文／cd 層數錯誤。

### H. E2E 截圖驗收管線（Runtime 保真，強制）

靜態（剝除 JS）截圖的渲染路徑與真實執行環境不同，**會漏抓執行期版面錯位**（實戰案例：插圖頁在靜態版「正常」、執行版破版）。交付前必須以 runtime 保真方式逐頁截圖審查。

1. **截圖方式**：Chrome headless `--headless=new --disable-gpu --hide-scrollbars --screenshot=OUT.png --window-size=W,H --virtual-time-budget=8000 "file:///路徑.html#/N"`——**保留全部 JS**，以 hash 深度連結逐頁導航；嚴禁剝除 `<script>` 後截圖。
2. **分段捕獲**：單次畫布高度 **>19,600px 會產生空白渲染帶偽影**（headless 光柵化極限）——以每段 ≤18 頁分段捕獲（檔名 a_NN.png／b_NN.png），再以 PowerShell System.Drawing 切片為 1920×1080 單頁 PNG。
3. **視窗重現**：除設計尺寸外，必須另以**使用者實際視窗尺寸**（如 1932×1015）複驗一次。
4. **九大檢核類別**（逐頁目視審查，pi.read 讀入截圖）：①文字重疊 ②文字被覆蓋 ③圖像重疊 ④配圖內容或線段錯置 ⑤文字大小≥18px ⑥重點與提示（qstrip／加粗）⑦卡片內容空洞 ⑧版面空洞 ⑨版面規格雷同。
5. **驗證時序鐵律**：檢查必須在「**最終修復後**」的檔案狀態執行——多輪修補、環境格式化器每輪改寫（有序清單重編號、引號樣式、屬性重排）、div 數≠grep 行數，都會造成時間差偽結果。
6. **修復閉環**：每輪修復後必須**重新截圖該頁驗證 → 全綠始得簽入**；不帶病簽入。
7. **已知偽影與盲點表**（實戰淬鍊）：超高畫布空白帶（>19,600px）／靜態版假正常／格式化器改寫／**重複 style 屬性須 HTML 解析器層級檢查**（grep 鄰接樣式會漏；行級檢查器會將跨元素同行雙 style 誤判——堆疊標籤一律折行）／has-guard 僅查開頭行會漏多行卡內重複／深度連結 hash 導航是唯一保真逐頁方式。
8. **抽樣策略**：全量 35+ 頁逐頁讀圖成本高——至少抽樣：封面、方法論頁、二選一、duo 整合頁、配圖頁、表格頁、quiz 頁、總結頁等**每一種版型各一**；修復後再對該版型其餘頁面複驗。

## 十四、直接編寫 HTML 簡報鐵律（嚴禁以 Python 生成簡報內容）

1. **直接手刻/編輯 HTML**：
   - 凡製作、修改、調整或重構任何 HTML 簡報時，**必須直接編寫與修改 HTML 檔案本體**。
   - 嚴格禁止撰寫 Python 腳本（如以 Python 拼接 HTML 字串、維護巨大字典資料結構再跑迴圈輸出 HTML、建立批次產生器等模式）來間接生成簡報內容與投影片結構。間接生成模式會造成結構失真、格式化脫節、二次排版地獄與除錯斷層。
2. **測試與驗證之合法工具定位**：
   - 測試、驗證、稽核與幾何掃描階段，**完全允許且鼓勵使用自動化腳本**（如 Python 驗證腳本、Headless Chrome / Playwright / Puppeteer 截圖與 DOM 邊界掃描工具、用語合規檢查器等）。
   - 腳本的職責嚴格局限於「**唯讀分析、邊界計算、合規體檢與缺陷通報**」，不得用於覆寫或產生 HTML 簡報原始碼。
