# 系統分析文件集方法論（System Analysis Document Set）

## when_to_use

- 執行研發 Stage-Gate Phase 3（系統分析）或重構既有系統分析文件集
- 將 SRS 轉化為架構與設計藍圖時

## document_set_structure（13＋ADR）

| # | 文件 | 要點 |
| --- | --- | --- |
| 00 | 文件集總覽 | 目的/系統概述/結構索引/**新舊對照表**/關鍵設計決策彙整/後續建議/總結 |
| 01 | 使用者角色與權限 | RBAC＋租戶/據點模型＋特權分層（跨租戶≠跨店）＋帳號生命週期 |
| 02 | 功能規格概述 | 功能架構分層＋領域索引（與 SRS 雙向引用，不重複規格） |
| 03 | 技術架構 | 分層架構＋技術堆疊＋橫切關注＋模組↔FR 映射 |
| 04 | 系統整合與資料流 | API 標準（OpenAPI/冪等/錯誤模型/分頁）＋整合點表＋主要資料流圖＋網路邊界 |
| 05 | 資料庫設計 | ER＋關鍵欄位＋動態超邊（樞紐投影）＋資料規則（軟刪/樂觀鎖/正規化欄） |
| 06 | 系統安全與使用者體驗 | 零信任/RLS/金鑰＋UX 原則（識別橫幅/RWD/AA/錯誤分級） |
| 07 | 核心引擎與狀態機 | 核心狀態機＋守衛＋職能分離流＋領域引擎（如法規對齊引擎） |
| 08 | 風險評估 | **九類**：競爭/技術/隱私/接受度/商業模式/法律/資安/穩定性/資料準確性＋緩解＋證據 |
| 09 | 系統整合與發佈策略 | 調度器/沙盒/備份＋CI/CD＋**離線安裝包**＋分階段發佈＋健康指標＋回滾 |
| 10 | 監控與營運分析 | 監控架構（API/管道/排程/DB/安全五層）＋KPI 體系＋營運分析＋異常對應表邊界 |
| 11 | 未來展望與進化路徑 | 演進路線圖＋技術演進＋策略合作＋退役原則 |
| 12 | 擴充與增強功能 | 擴充（觸發條件+架構預留）＋各利害關係人視角增強＋增強原則 |
| — | ADR/ | 編號決策：背景/決策/後果/替代案 |

## procedure_steps

1. 凍結上游基線（SRS）→ 2. 先寫 03 技術架構定調 → 3. 05/07 深化 → 4. 01/02/04 由映射反向補全 → 5. 06/08/09/10/11/12 橫切收尾 → 6. 00 總覽（對照表/決策彙整）收口。

## pitfalls

- 「模組數對上」≠逐條覆蓋——須逐 FR 映射表
- 狀態機漏例外態（過號/部分/退回/重開）與併發守衛
- 事件匯流無持久化（僅廣播）——採交易寄件匣
- 權限模型混淆跨店與跨租戶；背景工作繞過範圍
- 需求文件內部矛盾（同主題兩處規則相反）
- 新增章節後舊引用未更新（重構須附對照表）

## verification_steps

- 逐 FR→模組/實體/事件/守衛/驗收映射齊備
- 狀態機全轉移表含角色守衛與補償
- 九類風險逐類有緩解與證據
- 第三方審查 findings 對照表全數銷號
- 文件間交叉引用形成網絡（無孤島）
