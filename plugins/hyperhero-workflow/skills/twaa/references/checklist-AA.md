## 類別一：圖片

### 項目 1 — 有意義圖片的替代文字
- **等級**：A
- **必須符合**：是
- **說明**：網頁中有意義的圖片 `<img>` 元素，須以 `alt` 屬性提供對應的替代文字說明
- **稽核碼**：HM1110100E
- **評量方式**：
  1. 找出所有 `<img>` 元素
  2. 確認每個有意義的圖片都有 `alt` 屬性，且 `alt` 非空字串（裝飾性圖片則應為空 `alt=""`）
  3. 確認 `alt` 文字能清楚描述圖片在文件中的功能與內容
- **常見問題**：
  - 缺少 `alt` 屬性
  - `alt` 為「圖片」、「image」、「photo」等無意義文字
  - 把圖片檔名當作 `alt`（如 `alt="banner_01.jpg"`）
- **修正範例**：
  ```html
  <!-- 錯誤 -->
  <img src="logo.png">
  <img src="logo.png" alt="圖片">

  <!-- 正確 -->
  <img src="logo.png" alt="台灣無障礙協會標誌">

  <!-- 裝飾性圖片（不需要替代文字）-->
  <img src="decoration.png" alt="" role="presentation">
  ```

---

### 項目 2 — 複雜圖片的長描述
- **等級**：A
- **必須符合**：是
- **說明**：針對交通圖、流程圖、組織圖等資料圖片，除圖片標題文字外，須另外提供詳細的說明文字
- **稽核碼**：HM1110103E
- **評量方式**：
  1. 找出複雜圖片（流程圖、圖表、組織圖等）
  2. 確認有提供 `longdesc` 屬性連結或在鄰近位置提供說明文字
- **修正範例**：
  ```html
  <!-- 方法一：鄰近說明文字 -->
  <figure>
    <img src="org-chart.png" alt="公司組織架構圖">
    <figcaption>詳細說明：董事長下設總經理，總經理下設業務部、行政部、技術部三個部門...</figcaption>
  </figure>

  <!-- 方法二：aria-describedby 連結至說明文字 -->
  <img src="flow.png" alt="申請流程圖" aria-describedby="flow-desc">
  <p id="flow-desc">流程說明：步驟一填寫申請表，步驟二送審，步驟三核准...</p>
  ```

---

### 項目 3 — CAPTCHA 替代驗證方式
- **等級**：A
- **必須符合**：否（視網頁是否使用 CAPTCHA 而定）
- **說明**：圖片驗證碼應提供其他形式的驗證機制，如語音播放或 email 寄送
- **稽核碼**：GN1110111E
- **評量方式**：
  1. 確認網頁是否有 CAPTCHA 驗證碼
  2. 若有，確認是否提供至少一種替代方式（語音、email、簡訊等）

## 類別二：版面結構

### 項目 3b — 單一 h1 標籤
- **等級**：A
- **必須符合**：是
- **說明**：網頁是否都有使用 `<h1>` 標籤，且每個網頁中只有一個 `<h1>` 標籤
- **稽核碼**：HM1130104E
- **評量方式**：
  1. 搜尋頁面中所有 `<h1>` 元素
  2. 確認只有一個 `<h1>`，且代表頁面主題
- **修正範例**：
  ```html
  <!-- 錯誤：多個 h1 -->
  <h1>網站名稱</h1>
  <h1>本頁標題</h1>

  <!-- 正確 -->
  <h1>本頁主要標題</h1>
  <h2>次要區塊</h2>
  ```

---

### 項目 4 — 巢狀標頭結構（h1–h6）
- **等級**：AA
- **必須符合**：是
- **說明**：網頁是否以巢狀標頭元素，並依 `<h1>` 至 `<h6>` 的順序來建立文件結構
- **稽核碼**：GN2240600E
- **評量方式**：
  1. 列出頁面所有標頭（h1~h6）
  2. 確認標頭層級不跳號（如從 h1 直接跳到 h3，中間缺少 h2）
  3. 確認標頭文字具描述性，能反映區塊內容
- **修正範例**：
  ```html
  <!-- 錯誤：跳號 -->
  <h1>頁面標題</h1>
  <h3>子區塊</h3>  <!-- 跳過了 h2 -->

  <!-- 正確 -->
  <h1>頁面標題</h1>
  <h2>主要區塊</h2>
  <h3>子區塊</h3>
  ```

## 類別三：鍵盤操作

### 項目 5 — 所有功能可用鍵盤操作
- **等級**：A
- **必須符合**：是
- **說明**：網頁各項功能、連結、控制元件等，皆可透過鍵盤操作
- **稽核碼**：GN1210101E
- **評量方式**：
  1. 使用 Tab 鍵瀏覽所有互動元素
  2. 確認所有連結、按鈕、下拉選單、自訂元件皆可用鍵盤操作
  3. 確認沒有「鍵盤陷阱」（focus 無法離開某元素）
- **修正範例**：
  ```html
  <!-- 錯誤：使用 div 模擬按鈕，無法鍵盤操作 -->
  <div onclick="doSomething()">點我</div>

  <!-- 正確：使用 button 或加上 tabindex 及 keyboard 事件 -->
  <button onclick="doSomething()">點我</button>

  <!-- 或自訂元件加上 ARIA role 及鍵盤事件 -->
  <div role="button" tabindex="0"
       onclick="doSomething()"
       onkeydown="if(event.key==='Enter'||event.key===' ')doSomething()">
    點我
  </div>
  ```

## 類別四：檔案下載

### 項目 6 — 下載檔案標示名稱與格式
- **等級**：A
- **必須符合**：否（視網頁是否提供下載而定）
- **說明**：網頁中提供下載的檔案，均有標示其檔案名稱與檔案格式
- **稽核碼**：GN1320202E
- **評量方式**：
  1. 找出所有下載連結
  2. 確認連結文字中包含檔名與格式（如 PDF、Word、Excel）
- **修正範例**：
  ```html
  <!-- 錯誤 -->
  <a href="report.pdf">下載報告</a>

  <!-- 正確 -->
  <a href="report.pdf">2024 年度報告（PDF，1.2MB）</a>
  ```

## 類別五：導覽功能

### 項目 7 — 跳到主要內容鏈結
- **等級**：A
- **必須符合**：是
- **說明**：每一個網頁皆有跳到主要內容區鏈結，且為網頁上第一個可取得鍵盤焦點的鏈結
- **稽核碼**：GN1240100E
- **評量方式**：
  1. 按 Tab 鍵確認第一個焦點元素是否為「跳到主要內容」連結
  2. 確認該連結的目標（`<main>` 或相應 id）存在
- **修正範例**：
  ```html
  <!-- 在 <body> 最開頭加入 -->
  <a href="#main-content" class="skip-link">跳到主要內容</a>

  <!-- 可視情況隱藏，但 focus 時需顯示 -->
  <style>
  .skip-link {
    position: absolute;
    top: -40px;
    left: 0;
  }
  .skip-link:focus {
    top: 0;
  }
  </style>

  <!-- 目標區域 -->
  <main id="main-content">
    <!-- 主要內容 -->
  </main>
  ```

---

### 項目 8 — 鍵盤焦點高可見度
- **等級**：AA
- **必須符合**：是
- **說明**：使用鍵盤操作時，網頁中的鍵盤焦點具有高可見度，可明確得知焦點所在位置
- **稽核碼**：CS2240700E
- **評量方式**：
  1. 使用 Tab 鍵瀏覽，確認每個焦點元素都有明顯的視覺指示
  2. 確認 CSS 中沒有全域 `outline: none` 而無替代方案
- **修正範例**：
  ```css
  /* 錯誤：移除焦點樣式 */
  *:focus, a:focus, button:focus { outline: none; }

  /* 正確：提供自訂焦點樣式 */
  *:focus-visible {
    outline: 3px solid #005FCC;
    outline-offset: 2px;
    border-radius: 2px;
  }
  ```

## 類別六：圖片輪播

### 項目 9 — 輪播可暫停
- **等級**：A
- **必須符合**：否（視網頁是否有輪播而定）
- **說明**：圖片輪播、跑馬燈等，在使用鍵盤操作時，游標焦點移動至其上，可暫停並選取
- **稽核碼**：GN1220200E
- **評量方式**：
  1. 確認是否有自動播放的輪播或動態內容
  2. 確認鍵盤 focus 移入時可暫停，且提供暫停控制按鈕

## 類別七：色彩對比

### 項目 10 — 正常文字對比值 4.5:1（必須符合）
- **等級**：AA
- **必須符合**：是
- **說明**：網頁中的文字標題與內文，應和網頁背景色彩至少有 4.5:1 的對比值
- **稽核碼**：GN2140300E
- **評量方式**：
  1. 取出主要文字色與背景色
  2. 計算對比值是否 ≥ 4.5:1
  3. 可使用 WebAIM Contrast Checker (https://webaim.org/resources/contrastchecker/)

---

### 項目 11 — 大文字對比值 3:1
- **等級**：AA
- **必須符合**：否（視網頁是否有大文字而定）
- **說明**：大尺寸（18pt/24px 或 14pt/18.5px 粗體）的文字，應和背景色彩至少有 3:1 的對比值
- **稽核碼**：GN2140301E

---

### 項目 12 — 有意義圖示對比值 3:1
- **等級**：A
- **必須符合**：否（視網頁是否有有意義圖示而定）
- **說明**：網頁中各項有意義的圖示，其前景與背景色彩應至少有 3:1 的對比值
- **稽核碼**：GN2141101E

---

## 類別八：表單

### 項目 13 — 必填欄位文字標示
- **等級**：A
- **必須符合**：是
- **說明**：網頁中的表單設計，各項必填欄位均使用文字註明
- **稽核碼**：GN1330201E
- **評量方式**：
  1. 找出所有表單必填欄位
  2. 確認有文字說明（「必填」、「＊」需有說明、`required` 需搭配視覺說明）
- **修正範例**：
  ```html
  <!-- 錯誤：只有顏色或星號無說明 -->
  <label>姓名 <span style="color:red">*</span></label>
  <input type="text" required>

  <!-- 正確 -->
  <p>標示 * 為必填欄位</p>
  <label>姓名 <span aria-hidden="true">*</span>（必填）</label>
  <input type="text" required aria-required="true">
  ```

---

### 項目 14 — 表單驗證與焦點導向
- **等級**：AA
- **必須符合**：是
- **說明**：表單有檢查機制，使用者提交後，可完成檢查並將鍵盤焦點導向遺漏的必填欄位
- **稽核碼**：GN2330300E
- **評量方式**：
  1. 測試送出空白必填欄位的表單
  2. 確認有錯誤提示文字
  3. 確認焦點自動移到第一個錯誤欄位
- **修正範例**：
  ```javascript
  function validateForm() {
    const nameField = document.getElementById('name');
    const errorMsg = document.getElementById('name-error');
    if (!nameField.value.trim()) {
      errorMsg.textContent = '請填寫姓名';
      errorMsg.style.display = 'block';
      nameField.focus(); // 將焦點移到錯誤欄位
      nameField.setAttribute('aria-invalid', 'true');
      return false;
    }
  }
  ```
  ```html
  <label for="name">姓名（必填）</label>
  <input id="name" type="text" aria-describedby="name-error" aria-required="true">
  <span id="name-error" role="alert" style="display:none; color:red"></span>
  ```

## 類別九：行動裝置操作情境

### 項目 15 — 向上事件觸發功能
- **等級**：A
- **必須符合**：否（一般情境適用）
- **說明**：網頁中的功能均以向上事件（up-event）來完成，避免使用者無意間觸發執行並可移動指標來取消
- **稽核碼**：GN1250201E
- **評量方式**：
  1. 確認重要功能（按鈕、連結）是使用 `click` 事件（瀏覽器原生行為為 up-event）
  2. 確認沒有僅綁定 `mousedown`/`touchstart` 的關鍵操作而無取消機制
