# 軟體開發委託合約與驗收規格工程方法論 (Software Contract & Spec Engineering)

本技能沉澱自大規模企業級軟體專案（如跨國醫療資訊平台建置）之商業談判、合約簽署、附件脫敏與驗收防衛實戰經驗，為委託開發專案建立合約主文與雙附件之嚴密工程防線。

---

## 壹、何時使用 (when_to_use)

- 撰寫、重擬、審核軟體開發委託合約（客製化系統、微服務平台、App、跨國系統整合）。
- 產出合約法定不可分割附件：**《附件一：系統需求規格書》** 與 **《附件二：專案時程與驗收標準表》**。
- 設定分期付款進度（如 30%/30%/40%）、除不盡尾數處理規則及簽約預付款法律定性（排除定金沒收）。
- 約定純額契約或免營業稅條款，需徹底排除「未稅」、「營業稅 5%」、「含稅」等衝突字眼。
- 設定法律防衛邊界：遲延損害賠償上限（民法第 250 條第 2 項預定總額）、過失賠償最高上限（民法第 222 條，嚴格以各期實付或全案已付總額為限）。
- 切分專業領域責任（如醫療資訊系統排除臨床診斷決策、排除醫療器材軟體 SaMD 取證委託）。
- 處理外部商業資料庫採購責任（外購商業字典/禁忌庫未採購時，以自建資料處理，不得主張功能未達成）。
- 切分 AI 衍生耗材費用（外部商業 LLM 之 API 呼叫費、Token 消耗費由委託人全額負責）。
- 防範驗收後需求無限制追加（Scope Creep）：建立階段確認後之「功能異動補充費用協議（SFA）」。
- 智財權三層架構約定：客製化成果移轉、受託方既有 Background IP 保留與永久授權、寬鬆開源合規（SBOM）。

## 貳、合約文件架構三位一體原則 (core_architecture)

專案對外簽署文件必須嚴格維持「主文與雙附件三位一體」架構，各司其職，不得錯置：

```
┌────────────────────────────────────────────────────────┐
│                   軟體開發委託合約主文                 │
│  （法律權利義務、款項總額、分期付款、責任上限、智財權） │
└──────────────────────────┬─────────────────────────────┘
                           │ 參閱並包含（具同等法定效力）
            ┌──────────────┴──────────────┐
            ▼                             ▼
┌──────────────────────────┐  ┌──────────────────────────┐
│ 附件一：系統需求規格書   │  │ 附件二：專案時程與驗收表 │
│ - 嚴格六欄位標準矩陣     │  │ - 里程碑時程與付款進度表 │
│ - 排除人天、單價與成本   │  │ - 逐工項客觀檢測明細矩陣 │
│ - 純功能與技術交付標的   │  │ - 目標達成判定準則與時限 │
└──────────────────────────┘  └──────────────────────────┘
```

1. **合約主文**：僅載明專案總價、付款期程比例與條件、法律責任邊界與通用條款，表格內不直接嵌入巨型需求細項，僅註明「雙方同意另立並參閱附件一與附件二」。
2. **附件一（系統需求規格書）**：僅提供技術規格，**嚴格禁止洩漏人天、單價、內部角色分工與成本利潤**。
3. **附件二（專案時程與驗收標準表）**：提供可客觀量化、可單元驗證之檢驗方法與通過判定標準，杜絕主觀爭議。

## 參、合約主文十大必備防衛條款 (contract_clauses_framework)

在撰寫或審核合約主文時，必須具備以下十項關鍵條款，保護受託開發團隊之合法權益：

### 1. 專業領域與委任責任邊界切分（以醫療/特定法規為例）
- **資訊輔助工具定性**：系統所提供之排程、檢核、提示、報告產製或 AI 推論，本質均為「資訊決策輔助工具」，絕不可替代合法專業人員之法定專業判斷。
- **排除法定許可取證**：委託範疇嚴格排除代委託方取得主管機關許可（如「醫療器材軟體 SaMD」上市許可證），專業臨床/業務後果由委託機構獨立承擔。

### 2. 契約總價、分期比例與除不盡規則
- **金額表記**：契約總價採中文大寫與數字並列（如：新臺幣 3,300,000 元整，新台幣參佰參拾萬元整）。
- **除不盡尾數歸屬**：明訂「款項計算如有除不盡之尾數由第一期收取」，避免因尾數小數點引發雙方會計出納爭議。
- **預付款法律性質**：明訂「第一期款含簽約款，為專案建置預付款，不具民法定金沒收效果」，保障雙方正常履約與合意解約結算權益。

### 3. 純額免稅／稅務精確約定
- 若雙方協議為純額交易或免計營業稅：**全檔嚴格清除「營業稅 5%」、「含稅金額」、「未稅金額」等所有欄位與文字**，單一標明「金額（新台幣）」。
- 合約內關於賠償上限、違約罰款、後續維護費率等條文，一律改採「契約金額」、「實付金額」或「契約總價」，嚴禁殘留「未稅」字眼。

### 4. 遲延違約金與損害賠償總額預定上限（民法第 250 條）
- 因受託方事由逾期交付，經書面催告合理寬限期屆滿後，按遲延影響該階段契約金額，每日計罰千分之一（0.1%）。
- **責任雙重上限**：
  1. 該階段懲罰性違約金以該階段契約金額為上限。
  2. 全案累積遲延違約金總額，不得超過委託方就該階段或全案**實際已支付**受託方之款項金額為最高上限。

### 5. 一般過失損害賠償責任最高上限（民法第 222 條）
- 除故意、重大過失或侵害第三人智財權外，受託方因合約所生之一切違約金、瑕疵擔保代履行費及損害賠償：
  1. 特定階段爭議：以該階段價金為上限，且不得超出委託方就該階段**實際已支付**之金額。
  2. 全案累積爭議：嚴格以契約總價及截至索賠時**累計實際已支付**之款項總額為最高上限，絕不超出實際已付金額。
  3. 雙方明確約定排除間接損害、衍生損害、營業利益損失與懲罰性賠償。

### 6. 外購商業資料庫採購責任與免責原則
- 凡涉及特定專業資料庫（如藥物交互作用庫、專業醫學字典、外部付費圖資、金融報價流）：
  - 授權採購與持續訂閱費用由委託方全額負責。
  - 若委託方未提供或未採購，受託方系統僅依合約架構提供標準匯入介面與規則引擎，**依靠委託方自建之相關資訊由系統處理**。
  - 委託方**不得以自建資料或未採購商業資料庫未達第三方標準為由，主張功能未達成、拒絕驗收或扣留款項**。

### 7. 人工智慧（AI）衍生耗材費用歸屬
- 系統串接之外部商業大型語言模型或雲端推論 API（OpenAI、Google Gemini、Anthropic、Azure 等）：
  - API 呼叫費、運算 Token 消耗費、微調訓練託管費等一切 AI 衍生使用費用，均屬委託方之日常營運與業務推論耗材，非屬系統建置報酬。
  - 概由委託方全額負責並直接支付原廠或實報實銷，受託方建置與保固費用嚴格排除該等消耗性費用（受託方程式死迴圈異常暴衝除外）。

### 8. 各階段確認後之功能異動補充費用協議（Supplementary Fee Agreement, SFA）
- 各階段里程碑經委託方檢驗確認、簽署驗收證明書或視同驗收後，該階段功能即行凍結，免除受託方免費修改責任。
- 驗收後若委託方提出超出規格清單之功能新增、流程改版或邏輯重構，非屬免費保固或瑕疵擔保，雙方必須另行簽署**「補充費用協議書（SFA）」**。受託方重估工期與報價，簽署確認後始啟動開發。

### 9. 智慧財產權三層架構
1. **客製化成果**：客製開發之原始碼、UI 版型、DDL Migration 於委託方付清該階段款項後，著作財產權歸委託方所有。
2. **受託方既有技術（Background IP）**：通用架構、底層引擎（多租戶路由、規則引擎、通用 RBAC、轉換模組）智慧財產權仍歸受託方；授予委託方永久、不可撤銷、全球、非專屬之已付清使用授權；受託方享有重複使用權利。
3. **開源合規與 SBOM**：保證使用寬鬆開源協議（MIT/Apache-2.0/BSD），禁絕強傳染 Copyleft（AGPL/GPL-3.0）；總驗收提供完整軟體物料清單（SBOM）。

### 10. 重大瑕疵明確定義與營運不中斷保護
- **重大瑕疵（Level 1）**：身分識別配對錯誤、核心過敏檢核全失效、跨租戶個資外洩、核心流程完全中斷且無替代方案、不可篡改簽章雜湊損毀。
- **輕微缺失（Level 2/3）**：非關鍵外觀排版、文字潤飾、操作習慣差異，列入修復清單後，委託方得附條件同意驗收，**不得藉此阻卻整個階段之驗收與付款**。
- **資料人質防範與爭議款項處理**：爭議時僅得扣留爭議項目比例之款項，無爭議部分如期支付；受託方承諾爭議期間不得關閉運作中環境或刪除病歷資料。

## 肆、法定附件製作標準 (annex_standards)

### 一、附件一《系統需求規格書》標準六欄位

附件一為純技術交付規格，**必須刪除所有人天、工時、單價、利潤率及內部工程角色**。表格欄位強制規範為以下 6 欄：

| 項次 | 工項ID | 階段 | 任務編號 | 項目名稱 | 工項內容 |
| :---: | :---: | :--- | :---: | :--- | :--- |
| 1 | P1-W00-A | 第一階段｜MVP Demo | WBS-00 | Monorepo 骨架與型別管線 | 可重現的專案骨架、資料庫遷移基線與型別同步管線 |

- **工項編號規格化**：工項 ID 具備階段前綴（如 `P1-`、`P2-`、`P3-`），任務編號對齊 WBS。
- **免責告示置頂**：附件一開頭必須置入「外部商業資訊與藥品/專業資料庫免責特別約定」。

### 二、附件二《專案時程與驗收標準表》雙矩陣標準

附件二必須由兩大核心表格組成：

#### 1. 里程碑時程與付款進度表
| 期別 | 里程碑編號 | 里程碑名稱與工作範疇 | 預定完成日期 | 工項數量 | 支付比例 | 金額（新台幣） | 驗收交付標的與判定準則 |
| :---: | :---: | :--- | :---: | :---: | :---: | :---: | :--- |
| 第一期款 | **M1** | 第一階段｜簽約啟動與門診閉環（1個月） | 2026-12-01 | 31 項 | 30% | NT$ 990,000 | 雙方簽署生效、啟動會議完成，交付 31 項工項實機展示通過，簽署第一階段驗收證明書。含簽約款，除不盡尾數由本期收取。 |

#### 2. 客觀驗收檢測明細矩陣（逐工項對齊）
每項工項必須具備客觀檢測方式與明確判定準則，拒絕「功能正常」、「良好」等模糊字眼：
| 項次 | 工項ID | 工作項目名稱 | 主要交付/驗收成果 | 驗收檢測方式 | 目標達成方式與判定準則 |
| :---: | :---: | :--- | :--- | :--- | :--- |
| 13 | P1-W05-A | 處方開立與三級安全檢核 | 開方流程與檢核攔截證據 | 處方規則引擎三級檢核攔截測試（如未採購外購商業資料庫，以自建規則注入） | 依自建或提供之規則資料庫，輸入過量劑量或禁忌，引擎 100% 精確攔截，彈出警示並阻擋提交。未提供外購庫時以自建處理，不得主張功能未達成。 |

#### 3. 逾期視同驗收條款 (Deemed Acceptance)
- 交付後委託方應於 10~15 個工作天內完成審查並出具書面缺失。
- 逾期無正當理由未答覆，經受託方書面催告後 7 個工作天內仍未具體回覆者，自催告屆滿之次日起視為驗收通過，委託方不得拒付對應款項。

## 伍、合約產製標準作業程序 (procedure_steps)

```
步驟 1：商務邊界與基本資料鎖定
  ├─ 取得甲乙雙方實名資訊（公司全名、負責人、統一編號、營業地址、電話）
  ├─ 議定契約總價、工期月數、分期比例（如 30%/30%/40%）
  └─ 確認稅務原則（若免營業稅，啟動純額清除模式）
       ▼
步驟 2：合約主文生成與法條注入
  ├─ 套用十大防衛條款（責任上限、AI耗材、外購商業庫免責、SFA補充協議）
  ├─ 付款表格注入「除不盡第一期收取」與「預付款不具定金性質」
  └─ 簽署欄自動對齊甲乙方實名資料
       ▼
步驟 3：附件一純化（脫敏 6 欄位）
  ├─ 從研發 WBS / 開發計劃提取全量工程工項
  ├─ 徹底刪除人天、成本、工時、利潤與角色欄位
  └─ 格式化為：項次 / 工項ID / 階段 / 任務編號 / 項目名稱 / 工項內容
       ▼
步驟 4：附件二客觀化（時程＋檢測矩陣）
  ├─ 付款進度表與主文第 3.2 條精確對齊（金額、日期、工項數 1:1）
  └─ 逐工項訂定可執行的自動化測試腳本、操作流程與判定數值
       ▼
步驟 5：雙格式自動化產製（Markdown + DOCX）
  ├─ 撰寫專門 python-docx 產生腳本，配置專業樣式（Navy 標題、雙層邊框、淺藍表頭）
  ├─ 一鍵生成合約主文 .docx、附件一 .docx、附件二 .docx
  └─ 同步轉檔輸出 contract_text_for_review.txt 供法務或模型盲審
       ▼
步驟 6：全量合規掃描與交付驗證
  ├─ 掃描營業稅關鍵字（純額合約下違規次數必須為 0）
  ├─ 掃描中國大陸用語（違規次數必須為 0）
  └─ 金額雙向平衡驗算（各期加總 == 總價）
```

## 陸、常見致命陷阱 (pitfalls)

1. **金額除不盡引發出納糾紛**：
   - 330 萬或奇數金額除以特定比例時，若未在合約主文與附件明確約定「除不盡之尾數由第一期收取」，常導致兩造會計傳票產生 1 元差額而扣發款項。
2. **稅務字眼矛盾**：
   - 商業談判已確認為「實收總價」，合約主文卻沿用公版出現「未稅金額」、「營業稅 5%」、「含稅金額」，導致委託方主張應從總價中扣除 5% 稅款。
3. **責任無限上綱與間接損失**：
   - 未引用民法第 250 條第 2 項預定總額，未將違約金與損害賠償上限錨定在「各期實付金額」或「全案已付總額」，導致系統小 bug 面臨客戶百萬營業損失索賠。
4. **軟體團隊代攬醫療或專業法律責任**：
   - 未在合約中明確宣告為「資訊輔助工具」，若醫護人員看錯處方，軟體廠商容易被捲入醫療糾紛或連帶賠償訴訟。
5. **外購商業資料庫成為卡關藉口**：
   - 用藥交互作用或法規資料庫未採購，客戶在驗收時以「系統查不到最新藥品禁忌」為由主張功能不合格。合約必須載明「未採購時依靠自建資料處理，不得主張功能未達成」。
6. **外部 AI 費用由開發商吸收**：
   - 串接 GPT 或 Gemini，客戶上線後瘋狂測試產生高額 Token 費用，合約未將 AI 費用明確切分為「委託方日常營運耗材」。
7. **驗收後無限免費修改（Scope Creep）**：
   - 未簽署階段驗收證明書，或驗收後客戶持續修改流程。合約必須建立「階段確認後功能凍結」與「補充費用協議（SFA）」防線。
8. **附件一洩漏成本底牌**：
   - 將內部人天估算表、工程師單價或角色配置直接作為合約附件，導致客戶依此砍價或挑剔人員配置。
