# 內容關係 → 圖形形式對照

設計配圖的第一原則：**圖的形式由內容的關係結構決定**。先用一句話說出這張投影片的內容是什麼關係，
再從下表挑最貼切的形式。內容不同，圖就該長得不同；如果十張圖都是「一排圓角卡片＋箭頭」，就是沒有讀內容。

| 內容是這種關係 | 畫成 | layout | 要點 |
|---|---|---|---|
| 由外而內層層包圍（縱深防禦、洋蔥模型） | 同心圓或同心弧，核心用 NAVY 實心圓 | side | 每層一色（C 固定順序）；層名放在兩弧之間並加 `knockout()` 白底；上下或內外可分別放「角色／控制」 |
| 兩方以上往返互動（握手、認證協定，如 Kerberos、TLS） | 時序圖：每個參與者一條垂直生命線，訊息為水平箭頭 | side 或 full | 參與者頂端用 `badge()`；訊息依序由上而下；回應用虛線 |
| 上下疊加、每層依賴下一層（OSI、TCP/IP、分層架構） | 水平疊層，左右可加對照欄 | side | 每層一條色帶；跨層的東西用垂直括號標示 |
| 會回到起點的循環（PDCA、事件回應、SDLC） | 環狀：節點等距排在圓周，弧形箭頭相接 | side | 起點在 12 點鐘方向；中心放循環名稱 |
| 有起點終點的多步驟順序（金鑰生命週期、證據保管鏈） | 橫向時間軸：主幹線＋圓形站點＋下方說明卡 | full | 站名在上、說明在下；站點用 `circle` 主色＋白色 `icon` |
| 有條件判斷、會分岔的程序（考試／申請流程） | 流程圖：方框＋菱形判斷＋折線箭頭 | side | 是／否分支用不同顏色並標字；終點用 NAVY 實心框 |
| 兩個維度交叉分類（影響×可能性） | 四象限，軸線標高低 | side | 象限用 TINT 填色；最重要象限用主色框強調 |
| 同一維度上的程度差異（Open → Closed、DAC → MAC） | 水平光譜條＋刻度標記 | full | 兩端標極值；項目以標記點落在光譜上 |
| 兩者對照（優缺點、A vs B） | 左右對照兩欄或天平 | side | 兩邊用 C[0]／C[1]；中間放比較維度 |
| 上下從屬、分類（組織、分類樹） | 樹狀：根在上，折線連到子節點 | side 或 full | 同層等高；葉節點多時改橫向 |
| 集合包含或部分重疊 | 維恩圖或巢狀框 | side | 交集區域用文字標示，不用混色 |
| 元件放在不同區域並互相連線（DMZ、網段） | 區域框（虛線）＋設備圖示＋連線 | full | 區域用 TINT 填色；信任邊界用粗虛線 |
| 數量之間的計算關係（ALE = SLE × ARO） | 公式卡：每個項目一個色塊，運算子放大 | side | 每個變數下方寫中文定義與單位 |
| 數值大小比較（天數、成本） | 長條（橫向）＋數值標在條內 | side | 只有一個量就不用圖例；長條起點對齊 |
| 只是並列的幾個要點，彼此沒有關係 | 不畫圖 | — | **不要硬畫**，改用條列卡片版面 |

## 判斷不出關係時

- 重讀標題與條列，問：「讀者看完這張要記住的是順序、層次、差異，還是因果？」答案就是形式。
- 有兩種形式都可以時，選元素較少、一眼能看出重點的那種。
- 內容本身有疑問（事實不確定、條列不完整）才回頭查來源：影片用 `python3 scripts/extract_frames.py <影片> <起> <迄>`
  後用 Read 看 `sheet.jpg`；文件轉成圖片看對應頁。來源是用來查證內容，不是拿來照抄構圖；
  文字與事實以使用者的筆記為準，不自行增加事實。
